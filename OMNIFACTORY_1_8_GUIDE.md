# OmniFactory CRM 1.8 · Meta Lead Ads и управляемые настройки ботов

## Установка поверх 1.7 в Windows PowerShell

Остановите CRM и worker (`Ctrl+C`). Сохраните `.env` и действующий `CRM_ENCRYPTION_KEY`; новые выпуски конфигурации шифруются именно этим ключом. Из корня существующего проекта:

```powershell
Expand-Archive "$HOME\Downloads\OmniFactory_CRM_1_8.zip" -DestinationPath .\_crm_update_18 -Force
.\.venv312\Scripts\python.exe .\_crm_update_18\omnibot_crm\install_update.py --check
.\.venv312\Scripts\python.exe .\_crm_update_18\omnibot_crm\install_update.py --apply
.\.venv312\Scripts\python.exe -m pip install -r .\requirements.txt
.\.venv312\Scripts\python.exe -m alembic upgrade head
.\.venv312\Scripts\python.exe .\launcher.py diagnose
.\.venv312\Scripts\python.exe .\launcher.py start
```

Миграция `0009_growth_control` добавляет заявки Meta, историю выпусков ботов и правила полей. Установщик не копирует `.env`, базу или виртуальное окружение и делает резервные копии заменённых файлов. Сначала проверьте миграцию на ветке Neon, если производственная база общая.

## Подключение Meta Lead Ads

1. В разделе **Воронка** создайте воронку продаж с начальным этапом.
2. В **Продвижение / SEO** добавьте канал Facebook или Instagram и рекламный кабинет. Для отчётов нужен токен с доступом к рекламному аккаунту.
3. В блоке **Заявки из рекламных форм** укажите Page ID, воронку, отдельный Page Access Token с доступом к лидам, Meta App Secret и уникальный Verify Token (24+ символа). Секреты шифруются, повторно не отображаются.
4. В настройках Meta App укажите публичный HTTPS callback `https://ВАШ-ДОМЕН/api/v1/meta/lead-ads/ID_КАНАЛА` и тот же Verify Token; настройте подписку страницы на `leadgen`. Приложению и странице нужны соответствующие доступы на получение лидов. Проверьте права и режим приложения в кабинете Meta.
5. Отправьте тестовую заявку Meta. Webhook проверяет `X-Hub-Signature-256`, затем CRM получает контакт из Graph API через Page Access Token, создаёт клиента, сделку, касание кампании и запись заявки. Одинаковый lead ID обрабатывается один раз. Пустая форма не означает согласие на рассылку.

Если Graph API временно недоступен, endpoint отвечает ошибкой и не фиксирует неполный результат. Для надёжной эксплуатации настройте мониторинг ошибок и повторную доставку события со стороны Meta. При отсутствии ID кампании заявка всё равно создаётся, но остаётся без точной привязки к рекламной кампании.

Официальные материалы Meta: [получение лидов](https://developers.facebook.com/documentation/ads-commerce/marketing-api/guides/lead-ads/retrieving), [интеграция webhook с CRM](https://developers.facebook.com/documentation/ads-commerce/marketing-api/guides/lead-ads/quickstart/webhooks-integration). Доступ к реальному кабинету и права приложения зависят от вашей учётной записи; в архиве нет токенов.

## От рекламы до оплаты

На **Продвижение / SEO → От заявки до оплаты** видны заявки, разные клиенты, выигранные сделки, подтверждённые платежи, расход, CPL и ROAS в валюте кампании. Доступен Excel-файл. Одна подтверждённая оплата относится только к первому записанному рекламному касанию того же клиента CRM и только после даты касания. Разные валюты не суммируются и не конвертируются автоматически. Оплата клиента, заведённого отдельной карточкой бота, требует сопоставления карточек; CRM не считает разные записи одним человеком по догадке.

Этот выпуск принимает заявки Meta и читает статистику Meta/Google. Создание объявлений, управление бюджетами, обратная отправка офлайн-конверсий и OAuth-подключение кнопкой не реализованы в 1.8.

## Конструктор полей бота

В **Боты → Настройки → Поля** доступны варианты одиночного/множественного выбора, числа с пределами, дата, email, URL, секреты и прежние типы. Для поля можно задать обязательность, максимальную длину и простое условие видимости `другой_ключ = значение`. Видимость можно проверить внизу конструктора. Сервер повторно проверяет всё при публикации; зависимость от секретного поля и цепочки условий запрещены, чтобы конфигурация была однозначной.

В **Версии** нажмите **Проверить и опубликовать**. CRM шифрует снимок заполненных и видимых полей, продуктов и опубликованных сценариев. После *первой* публикации подписанный `/api/v1/bot-config` выдаёт только последний снимок; редактирование черновика его не меняет. Кнопка **Вернуть эту версию** создаёт новый выпуск с прежним содержимым и сохраняет всю историю. До первой публикации прежний режим чтения текущих настроек оставлен ради совместимости.

`ingest_secret` используется CRM для аутентификации запросов и не входит в выдаваемую конфигурацию; его смена начинает действовать сразу. Исполнение сценариев и новых параметров требует, чтобы код самого бота читал шлюз и применял значения. Архив не меняет код работающего Food_Porn.
