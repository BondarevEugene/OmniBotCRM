# OmniFactory CRM · центр запуска

`launcher.py` — единая консоль для Windows, Linux и Google VM. Запускайте из корня проекта **тем Python, в который установлены зависимости CRM**. В Windows без активации окружения:

```powershell
.\.venv312\Scripts\python.exe .\launcher.py diagnose
.\.venv312\Scripts\python.exe .\launcher.py migrate
.\.venv312\Scripts\python.exe .\launcher.py start
```

Админка: `http://127.0.0.1:8000/login`; просмотр таблиц на смартфоне: `http://127.0.0.1:8000/m`. Остановка `Ctrl+C` завершает веб и worker. **Не запускайте второй `worker`, когда работает `start`**: `start` уже включает один worker.

## Команды

| Режим | Результат |
| --- | --- |
| `diagnose` | Проверяет файлы, Python, зависимости, настройки, подключение к базе, актуальность миграции, администратора и до 20 ботов. Ничего не мигрирует. |
| `diagnose --offline` | Те же локальные проверки без соединения с базой. |
| `diagnose --deep` | Дополнительно запускает pytest и установленный Ruff. Отсутствие этих необязательных инструментов отмечает как пропуск. |
| `migrate` | **Явно** выполняет `alembic upgrade head`. Перед этим остановите веб и worker; для рабочей Neon базы сначала сделайте branch или резервную копию. |
| `start` | Запускает веб и worker вместе. Если один упал, останавливает другой и сообщает код завершения. |
| `web` | Запускает только веб. Удобно при внешнем supervisor для worker. |
| `web --reload` | Только разработка: автоматическая перезагрузка кода. |
| `worker` | Запускает только фоновую обработку. Запускайте ровно одну копию. |

Дополнительные параметры: `--port 8001`, `--host 127.0.0.1`, `--timeout 15`, `--no-color`. Для публичного адреса можно явно указать `--host 0.0.0.0`, но нужен HTTPS-прокси и ограничение доступа к админке. По умолчанию веб доступен только на этой машине.

## Первый запуск или обновление

1. Запустите `diagnose`. При отсутствии `.env` скопируйте `.env.example` и заполните `SESSION_SECRET` (не менее 32 символов), `DATABASE_URL`, `CRM_ENCRYPTION_KEY`. **Никогда не меняйте уже действующий `CRM_ENCRYPTION_KEY`**: он нужен для чтения сохранённых настроек ботов.
2. Установите зависимости: `.\.venv312\Scripts\python.exe -m pip install -r .\requirements.txt`. Пакет `httpx[socks]` покрывает среды с SOCKS-прокси.
3. Запустите `migrate`, затем `diagnose`. Версии схемы базы и локального кода должны совпасть.
4. Если владельца ещё нет, задайте уникальный `ADMIN_PASSWORD` в `.env` и выполните `.\.venv312\Scripts\python.exe -m crm.cli create-admin --email ваш@адрес`.
5. Запустите `start` и откройте админку. Каждого нового бота добавляйте в разделе «Боты и параметры», а настройки, секреты и эквайеры — в его карточке.

При установке обновления из архива используйте `install_update.py --check`, затем `--apply` и повторите шаги 2–3. Существующий `.env` установщик не перезаписывает.

## Что означают результаты

- **FAIL** у критической проверки блокирует `web`, `worker` и `start`. В `migrate` проверка текущей схемы пропущена намеренно, чтобы можно было обновить устаревшую базу.
- **WARN** напоминает о неполной конфигурации: например, нет ключа шифрования, администраторов или подписи событий у конкретного бота. Это не препятствует локальному просмотру CRM.
- По каждому из первых 20 ботов показываются наличие `ingest_secret`, токена рассылки, количество активных эквайеров и время последнего события. **Секреты не показываются.** Значения больше 20 доступны в самой CRM.
- Отчёт `storage/diagnostics/last_report.json` содержит статусы и счётчики без ключей и паролей; это локальный файл и он не входит в архив поставки.

На Google VM для долгой работы используйте отдельные системные сервисы или Docker Compose из проекта. `launcher.py` удобен для ручной диагностики и локального запуска; работающий сеанс терминала не заменяет системный менеджер процессов. Для Neon используйте `postgresql+psycopg://...?...sslmode=require` и передайте секреты через среду сервиса.
