# Универсальное администрирование ботов

Каждый бот управляется через **«Боты» → «Настройки»** либо `/bots/{id}/configure`. Food Porn, следующие Telegram-боты и проекты используют один интерфейс. Специальный `/food-porn` показывает только его исходные клиентские/производственные данные.

Начиная с выпуска 1.8, поля поддерживают варианты выбора, числовые пределы, обязательность и показ по значению другого поля. Во вкладке **Версии** можно проверить и опубликовать конфигурацию, затем вернуться к более раннему снимку без удаления истории. После первой публикации черновые изменения не отдаются боту до следующего выпуска. Инструкция по обновлению и подключению Meta Lead Ads — [OMNIFACTORY_1_8_GUIDE.md](OMNIFACTORY_1_8_GUIDE.md).

## 1. Общая карточка

При регистрации задайте системный `key` и понятное `name`. `key` используется в подписи событий, связях клиентов и заказов, поэтому после регистрации не меняется; `name`, `description` и флаг активности изменяются на странице бота. Системный ключ не является секретом. Любой bot ID может иметь собственную пару ключей `ingest_secret` и `telegram_token` в произвольных настройках. Секреты вводятся один раз и затем показываются только как маска.

## 2. Платежные аккаунты внутри карточки

Для **каждого** бота отдельно сохраняются аккаунты Portmone (`login`, `password`, `payee_id`), WayForPay (`merchant_account`, `secret_key`), LiqPay (`public_key`, `private_key`) и PayPal Orders v2 (`client_id`, `client_secret`, `merchant_id`, `environment`). Поля зашифрованы одним `CRM_ENCRYPTION_KEY`; повторное сохранение с пустыми секретными полями оставляет старые значения. Переключатель «Разрешить проверку оплат» включает или выключает аккаунт. Выключенный аккаунт не используется для сверки, даже если старые ключи есть в `.env`.

Можно добавить другого эквайера с произвольным набором строковых полей JSON, например `{"merchant_id":"...","api_secret":"..."}`. Он сохранится зашифрованным и будет виден в карточке. Автоматическая **проверка** транзакций реализована для Portmone, WayForPay, LiqPay и PayPal Orders v2; новому провайдеру потребуется отдельный проверяющий адаптер. Запись настроек сама по себе не выполняет платеж и не подключает аккаунт к исходному коду бота.

Старые общие ключи `.env` поддерживаются для Food Porn до переноса их в карточку. Новые боты используют только свой аккаунт. Если для Food Porn сохранен аккаунт в карточке, он всегда имеет приоритет над старым `.env`.

## 3. Собственные поля в любом порядке

У каждого бота неограниченное число ключей, каждый имеет отдельные название, группу, описание, тип и значение. Группу можно назвать произвольно. Кнопки **↑ / ↓** задают порядок на странице. Повторное сохранение существующего ключа обновляет его. Чтобы поменять системное имя ключа, создайте новый и удалите старый, затем обновите код бота, который на него ссылается.

| Тип | Ввод | Передача боту в `/api/v1/bot-config` |
| --- | --- | --- |
| text, multiline | Текст и большие тексты | Строка |
| integer, number | Целое и дробное число | Число |
| boolean | `true` или `false` | Boolean |
| json, list | JSON объект либо JSON массив | Объект/массив |
| url, email, date | HTTPS URL, почта, `YYYY-MM-DD` | Строка |
| secret | Токен, пароль, API-ключ | Значение приходит только аутентифицированному процессу бота |

`ingest_secret` используется для подписанных событий бота и не возвращается в JSON настройки. `telegram_token` может использовать worker CRM для разрешенных рассылок. `source_database_url` хранит адрес исходной базы для CRM, не возвращается процессу бота и имеет приоритет над старой переменной среды Food Porn. Ключи, оканчивающиеся на `_password`, `_secret`, `_token`, `_api_key` или `_private_key`, можно сохранить только с типом `secret`.

## 4. Где появляются данные клиентов

Для каждого нового бота создайте его запись и передайте из его кода событие `customer.upsert` через `integrations/send_event.py`. Один Telegram ID в разных ботах хранится отдельно через `crm_identities`. События `order.upsert`, `payment.upsert`, `bot.heartbeat`, `bot.error` и `marketing.touch` пополняют соответствующие разделы. Для Food Porn дополнительно есть импорт из его Neon-базы (подробнее в [FOOD_PORN_SETUP.md](FOOD_PORN_SETUP.md)). Параметры CRM начнут управлять самим ботом, когда он будет получать их через подписанный `GET /api/v1/bot-config`; без изменения кода это административный реестр, а не удаленный переключатель процесса.

## Продукты в одном Telegram-боте

В разделе `/bots/{id}/configure` можно зарегистрировать любое число продуктов внутри одного Telegram-аккаунта. Профили **Telegram**, **Гастрономическое меню** и **Обои-манифестации** только объявляют незаполненные типизированные поля; они не назначают цену, токен, VIP-доступ или платежный аккаунт. Повторное применение не стирает введённые значения. Поле со статусом «нужен ввод» не отдается в API конфигурации и не считается действующим секретом. Для собственных продуктов предусмотрена произвольная запись ключа, названия и состояния. Подробнее по исходникам: [FOOD_PORN_REPOSITORY_ANALYSIS.md](FOOD_PORN_REPOSITORY_ANALYSIS.md).

При будущей интеграции бот может передавать `data.module_key` в подписанных событиях CRM. Событие принимается только для зарегистрированного продукта этого бота; заказы и платежи получают такую же привязку, чтобы разделять счётчики. Статус продукта в CRM — административное состояние; пока исходный код бота не читает `/api/v1/bot-config`, он не выключает и не включает обработчики сам.

## Обновление до 1.7 в PowerShell

Распакуйте `OmniFactory_CRM_1_7.zip` в `_crm_update`, затем из корня старой CRM:

```powershell
.\.venv312\Scripts\python.exe .\_crm_update\omnibot_crm\install_update.py --check
.\.venv312\Scripts\python.exe .\_crm_update\omnibot_crm\install_update.py --apply
.\.venv312\Scripts\python.exe -m pip install -r .\requirements.txt
.\.venv312\Scripts\python.exe -m alembic upgrade head
```

Файл `.env` и база остаются на месте; установщик сохраняет старые версии заменяемых файлов. После миграции перезапустите веб-сервер и worker. Сохраните текущий `CRM_ENCRYPTION_KEY`: смена ключа без миграции сделает старые секреты нечитаемыми.

Сценарии, новые платёжные кабинеты, реклама и мобильная версия описаны в [OMNIFACTORY_1_7_GUIDE.md](OMNIFACTORY_1_7_GUIDE.md).
