# Food Porn в OmniFactory CRM: установка и заполнение

Страница **`/food-porn`** показывает исходные данные Food Porn. Общие данные, эквайеры и произвольные параметры настраиваются в **универсальной карточке бота** `/bots/{id}/configure`, как для любого другого бота. До подключения настоящей базы Neon здесь нет реальных клиентов и заказов. Никаких ключей и клиентских записей в архиве нет. См. [BOT_ADMINISTRATION.md](BOT_ADMINISTRATION.md).

## 1. Установить обновление на Windows

В PowerShell перейдите в существующий проект `C:\Users\bonda\PycharmProjects\omnibot_crm`. Скачайте новый архив в «Загрузки» и выполните:

```powershell
Expand-Archive "$HOME\Downloads\OmniFactory_CRM_1_7.zip" -DestinationPath .\_crm_update -Force
.\.venv312\Scripts\python.exe .\_crm_update\omnibot_crm\install_update.py --check
.\.venv312\Scripts\python.exe .\_crm_update\omnibot_crm\install_update.py --apply
.\.venv312\Scripts\python.exe -m pip install -r .\requirements.txt
.\.venv312\Scripts\python.exe -m alembic upgrade head
```

Первый запуск установщика только перечисляет изменения. Второй копирует их и складывает старые версии замененных файлов в `.crm_update_backups`. `.env`, локальная база и виртуальные окружения не копируются. Проверьте, что появилась миграция `alembic/versions/0008_ads_and_customer_workspace.py`. Архив может лежать в другой папке — тогда измените путь в `Expand-Archive`.

## 2. Зарегистрировать бота

Откройте `/food-porn` от учетной записи владельца и нажмите **«Зарегистрировать бота»**, если он еще не создан. Если `food_porn` уже есть, операция сохранит его данные. Начальные секреты, цены и технические параметры автоматически не добавляются: вы вносите их в карточке самостоятельно и в нужном порядке.

| Раздел | Известные настройки из предоставленного снимка исходников | Откуда появляются в CRM |
| --- | --- | --- |
| Клиенты | Telegram ID, имя, телефон, язык, страна, город | Синхронизация из `customers` |
| Меню | Клиент, этап, блюда и напитки по категориям | `menus`, `menu_items` |
| Производство | Статус генерации каждого блюда, признаки загруженных фотографий | `menu_items`, `menus` |
| Файлы | Вид документа и путь на сервере бота | `generated_files`; пути сами по себе не скачивают файл |
| Платежи | Бот может заявлять об оплате через Portmone | В CRM это `reported_paid` без выручки; проверку проводит CRM по платежному провайдеру |
| Тарифы | Меню электронное/печать, AI-коллаж/постер | Введите **действующую** цену в разделе «Каталог и стоимость» после проверки бота |
| Технические параметры | Модель GPT Image, размер, качество, параллельность, параметры печати | Произвольные поля `/bots/{id}/configure`, заполняются вручную |

**Изменения параметров в CRM пока не обновляют настройки живого бота**: сначала интегрируйте в него чтение подписанного API `/api/v1/bot-config`. И наоборот, цена каталога CRM сама по себе не меняет цену в платежной ссылке бота.

## 3. Подключить клиентов и меню

На `/bots/{id}/configure` примените профиль **Telegram · общие параметры** и сохраните поле **«Адрес исходной базы»** (`source_database_url`) как секрет. Это предпочтительный вариант для синхронизации через интерфейс и worker. Можно сохранить старую конфигурацию в `.env` CRM — она будет использована, пока поле бота не заполнено:

```dotenv
FOOD_PORN_SOURCE_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/neondb?sslmode=require
```

При общей Neon-базе CRM и бота адрес может совпадать с `DATABASE_URL`. Отдельный пользователь с правом `SELECT` для исходных таблиц удобнее для защиты от случайных изменений. Не публикуйте строку подключения и не отправляйте ее в чат. Если в боте адрес имеет вид `postgresql+asyncpg://...`, импортер переведет его на `psycopg` для чтения.

После сохранения `.env` перезапустите CRM; изменение поля карточки читается при следующем запросе/цикле worker. Отдельная консольная команда ниже пока читает только `.env`, поэтому для её проверки временно укажите URL там же:

```powershell
.\.venv312\Scripts\python.exe -m integrations.food_porn_import --dry-run
```

Затем нажмите **«Синхронизировать сейчас»** на `/integrations`, либо выполните консольный импорт (ему нужен URL в `.env`):

```powershell
.\.venv312\Scripts\python.exe -m integrations.food_porn_import
```

На странице появятся количество записей исходных таблиц, клиенты, меню, блюда, состояние генерации и файлы. Повторный импорт обновляет те же записи по ID бота и исходным ID, не создает дубликаты. Запущенный отдельным процессом `crm.worker` повторяет синхронизацию каждые 15 минут.

## 4. Завершить безопасную конфигурацию

| Что настроить | Где | Для чего |
| --- | --- | --- |
| `CRM_ENCRYPTION_KEY` | `.env` CRM | Шифрует секретные настройки ботов |
| `ingest_secret` | `/bots/{id}/configure`, профиль Telegram, тип secret | Подпись будущих событий Food_Porn → CRM; тот же секрет понадобится в коде бота |
| `telegram_token` | `/bots/{id}/configure`, профиль Telegram, тип secret | Только для разрешенных рассылок worker CRM; токен бота не нужно дублировать, если рассылки пока не запускаются |
| `source_database_url` | `/bots/{id}/configure`, профиль Telegram, тип secret | Зашифрованный адрес источника для UI и worker; не отдаётся боту в API |
| Portmone: логин, пароль, Payee ID | `/bots/{id}/configure`, «Платежные эквайеры» | Отдельный аккаунт бота для сверки платежа с реальными суммой, валютой и номером заказа. Старые `.env` ключи остаются только совместимостью для Food Porn. |
| Действующие тарифы | `/food-porn`, «Каталог и стоимость» | Управленческий каталог CRM; дополнительно обновить стоимость в Food_Porn |

Старый обработчик Food_Porn содержал демонстрационное подтверждение оплаты кнопкой и другую ветку, доверяющую webhook. **Не используйте флаг `is_paid` или `payment_id` из этих таблиц как подтвержденный доход**, не отправляйте чистые материалы автоматически до проверки настоящего платежа у провайдера. Импорт сохраняет заказ с суммой 0 и статусом `reported_paid`; фиктивной выручки он не создает.

Регистрация контакта в боте сама по себе не является согласием на маркетинговую рассылку. CRM не проставляет такое согласие при импорте.

## Что потребуется для полного запуска

Для заполнения реальными данными нужен доступ CRM к фактической базе Food_Porn и сверка ее актуальной схемы с миграцией бота. Для текущих цен и работающих платежей понадобятся реальные настройки магазина и исправленная логика оплаты в проекте Food_Porn. Для мгновенных событий и управления параметрами из CRM понадобится небольшое обновление кода самого бота. Все секреты вводите в своей среде; их нет в поставке.
