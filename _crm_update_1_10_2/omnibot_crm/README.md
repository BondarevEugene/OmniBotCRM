# OmniFactory CRM · веб-проекты, боты и продвижение

## Центр запуска и диагностики

В Windows PowerShell используйте Python уже установленной среды проекта. `launcher.py` показывает состояние Python, зависимостей, конфигурации, схемы Alembic, базы, администратора и ботов. Он не выводит секреты и не меняет базу при обычной диагностике. Подробности: [LAUNCHER_GUIDE.md](LAUNCHER_GUIDE.md).

```powershell
.\.venv312\Scripts\python.exe .\launcher.py diagnose
.\.venv312\Scripts\python.exe .\launcher.py diagnose --deep
.\.venv312\Scripts\python.exe .\launcher.py migrate
.\.venv312\Scripts\python.exe .\launcher.py start
```

`start` запускает веб и один CRM worker в одном окне; `Ctrl+C` останавливает оба. Админка: `http://127.0.0.1:8000/login`, просмотр таблиц на смартфоне: `/m`. Отдельно доступны `web`, `web --reload` для разработки и `worker`. `diagnose --offline` проверяет проект без подключения к базе; `--deep` запускает pytest и Ruff, если они установлены. Структурированный отчёт сохраняется в `storage/diagnostics/last_report.json` без ключей и паролей. `migrate` нужно запускать **отдельно**, остановив веб и worker; запускатель никогда не применяет миграции при старте. Для Google VM предпочтителен системный сервис или Docker Compose с отдельным worker, а не интерактивный терминал launcher.

**Обновление 1.8:** [OMNIFACTORY_1_8_GUIDE.md](OMNIFACTORY_1_8_GUIDE.md) — Meta Lead Ads, путь от заявки до подтверждённой оплаты, интерактивные поля и версии конфигурации ботов. **Универсальная карточка каждого бота:** [BOT_ADMINISTRATION.md](BOT_ADMINISTRATION.md). Подключаемые профили Telegram, меню и обоев создают незаполненные поля без цен и секретов. Разбор исходников Food Porn и контракт подключения: [FOOD_PORN_REPOSITORY_ANALYSIS.md](FOOD_PORN_REPOSITORY_ANALYSIS.md). Для исходных данных меню есть [FOOD_PORN_SETUP.md](FOOD_PORN_SETUP.md). Предыдущая версия: [OMNIFACTORY_1_7_GUIDE.md](OMNIFACTORY_1_7_GUIDE.md). Обновление через `install_update.py` с предварительным просмотром и резервной копией заменяемых файлов.

Самостоятельная Python CRM для Food_Porn, второго Telegram-бота и следующих проектов. FastAPI + серверные Jinja-шаблоны + SQLAlchemy + PostgreSQL/Neon. Есть русская и английская версии интерфейса (основные разделы); светлая воздушная и темная темы. Название и исходники второго отдельного бота пока не предоставлены: он регистрируется в админке после получения его данных.

## Реализовано

- Закрытая админка: учетные записи администраторов, CSRF, сессии, журнал действий.
- Клиенты: создание вручную, фильтры по боту/источнику/тегу/статусу, карточка с историей и заметками, импорт CSV с проверкой совпадений, Excel-экспорт, связи с несколькими ботами.
- Боты: регистрация новых проектов, карточка `/bots/{id}`, сигнал `bot.heartbeat`, ошибки `bot.error`, состояние ключей и инциденты.
- Коммерция: заказы, платежи, расходы по валютам, журнал сверки. Платеж, помеченный ботом как `paid`, попадает в `reported_paid`; выручка учитывается только после запроса статуса напрямую у Portmone или WayForPay, LiqPay либо PayPal Orders v2 с проверкой магазина, заказа и суммы. Worker повторяет сверку раз в 5 минут. Для Portmone сейчас принимается только UAH.
- `/reports`: период и бот, приток клиентов, источники, коммерция, проекты, обращения, рассылки, CSV и версия для печати/PDF. Валюты не смешиваются; это операционный отчет.
- `/integrations`: видимость источников, журнал загрузок и запуск импорта Food_Porn; worker синхронизирует источник раз в 15 минут при заполненном зашифрованном `source_database_url` в карточке бота или запасном `FOOD_PORN_SOURCE_DATABASE_URL` в `.env`.
- `/commerce`: каталог товаров и услуг с SKU, состав заказа с ценой на момент покупки, сверка платежей и обзор заказов.
- Кампании: черновик, предварительный подсчет аудитории, запуск владельцем, пауза, журнал доставки, повтор после ответа Telegram 429, соблюдение согласия и блокировок. В фоне работает отдельный Python worker.
- Компании и контактные лица, несколько воронок со стадиями, сделки по типам IT-услуг и ожидаемому бюджету, создание проекта из выигранной сделки.
- Проекты: бюджет, домен, репозиторий, сроки, этапы исполнения, статус; обращения: ошибки, поддержка, запросы на изменение и приоритет.
- Входящие заявки `lead.upsert` и обращения `ticket.upsert` из бота; CRM создает контакт, сделку или тикет в рамках подписанного события.
- Мобильное пространство `/m`: сводка, поиск и Excel-экспорт 47 таблиц, ссылки на рабочие карточки, навигация к клиентам, ботам и рекламе. Полная CRM имеет адаптивные формы и действия на смартфоне; системные таблицы `/m/t/...` остаются только для чтения.
- API событий: HMAC SHA-256, окно 5 минут, уникальный `event_id`, идентификатор клиента внутри конкретного бота, синхронизация заказов и платежей. Исходные таблицы ботов не изменяются.
- Исходные таблицы Food_Porn `customers`/`menus` доступны для однократного импорта без выдумывания денежных сумм. Для второго бота требуется его фактическая структура или отправка событий через API.
- Две темы: светлая в голубых, синих и лиловых тонах по умолчанию, темная в переключателе; переключатель RU/EN в шапке. Основные дашборды, графики платежей и расходов, притока событий ботов, кликов и лидов.
- В карточке каждого бота произвольное число индивидуальных параметров (`text`, `multiline`, `integer`, `number`, `boolean`, `choice`, `multi_choice`, `json`, `list`, `url`, `email`, `date`, `secret`) с группами, порядком и описаниями. Параметры из профилей сначала остаются незаполненными и не включаются в runtime конфигурацию. Можно добавлять любое число продуктов внутри одного Telegram-бота; новые события и заказы помечаются `module_key` для раздельных счётчиков. Каждый бот имеет свои зашифрованные аккаунты Portmone, WayForPay, LiqPay и PayPal Orders v2; Redsys хранится без сверки. Секреты зашифрованы Fernet; `ingest_secret` и `telegram_token` используются CRM. Бот может получить заполненные параметры, продукты и опубликованные сценарии через подписанный `GET /api/v1/bot-config` по HTTPS; поддерживается ETag/304. Для каждой новой логики бота интегратор использует выданные настройки в его коде.
- Счета клиентам: черновик, строки услуг, номер, реквизиты продавца/покупателя, выставление, PDF с поддержкой кириллицы, привязка оплаты только к подтвержденному платежу той же суммы и валюты. Расход вручную можно связать с проектом; карточка проекта показывает оплаченные счета, расходы и баланс по валютам без выдуманного курса.
- Growth/SEO: рекламные каналы и кампании с UTM, дневные показы/клики/лиды/затраты, атрибуция клиента через `marketing.touch`, поисковые запросы и история позиций SEO, CSV и график. Meta Ads и Google Ads напрямую загружают дневную статистику по кампаниям при вводе действующих доступов в CRM; worker синхронизирует их ежечасно. Другие каналы используют подписанный импорт или ручной учет. Есть Excel-экспорт.

## Локальный старт

Python 3.12. В PowerShell:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`: уникальные `SESSION_SECRET` (минимум 32 символа), `ADMIN_PASSWORD`, секреты ботов. Приложение читает `.env` автоматически и не перезаписывает реальные переменные окружения. Локальный шаблон уже использует SQLite и `COOKIE_SECURE=false`; для Neon замените `DATABASE_URL` на строку подключения `postgresql+psycopg://...?...sslmode=require`.

```powershell
alembic upgrade head
python -m crm.cli create-admin --email admin@example.com
python -m crm.cli seed-bots
python -m crm.cli seed-crm
uvicorn crm.app:app --reload
```

Откройте `http://127.0.0.1:8000/login` (полная версия) и после входа `http://127.0.0.1:8000/m` (версия для смартфона). Во втором окне терминала с тем же окружением запустите `python -m crm.worker`. Для Docker выставьте переменные окружения в настройках сервиса, не включайте `.env` в образ.

**Если предыдущая версия уже установлена:** используйте обновление по инструкции [BOT_ADMINISTRATION.md](BOT_ADMINISTRATION.md), **сохраните свой `.env`**, прежде всего `CRM_ENCRYPTION_KEY`. Используйте Python действующей среды `.venv312`:

```powershell
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt
.\.venv312\Scripts\python.exe -m alembic upgrade head
```

Миграции до `0009_growth_control` добавляют продукты и сценарии ботов, рекламные кабинеты, заявки Meta, версии конфигурации и правила полей; прежние записи и администратор остаются. Если ключ `CRM_ENCRYPTION_KEY` уже установлен, сохраните его без изменений: при его потере прежние зашифрованные токены восстановить нельзя. Для первого включения шифрования сгенерируйте Fernet-ключ один раз и внесите его в `.env`. Заполните `INVOICE_SELLER_NAME` и `INVOICE_SELLER_DETAILS`, перезапустите веб и worker. На копии Neon базы проверьте совместимость до обновления рабочей ветки.

Для Google Compute Engine (VM) или локального Docker предусмотрен `compose.yaml`: после миграции `docker compose up --build -d` запускает веб и один worker. Веб-порт привязан только к `127.0.0.1:8080`; для публичного доступа поставьте HTTPS-прокси и ограничение доступа к админке. В VM используйте Neon, поскольку SQLite внутри контейнера не сохраняется при пересоздании.

Пароли и токены нельзя коммитить. Создание бота сопровождается его индивидуальным `ingest_secret` (в карточке при настроенном `CRM_ENCRYPTION_KEY`) или добавлением ключа в `BOT_INGEST_SECRETS`; `telegram_token` можно задать в карточке либо в `BOT_TOKENS` (только для рассылок). Секрет для приема событий должен иметь минимум 24 символа. Meta Ads и Google Ads подключаются в `/marketing` при наличии действующих API-доступов. Для других каналов можно использовать `integrations/send_marketing_metric.py` и отдельный секрет.

## Пример подключения бота

В `integrations/send_event.py` есть асинхронный отправитель. Укажите CRM URL, ключ `food_porn` либо зарегистрированный ключ второго бота, отдельный HMAC секрет и стабильный `event_id` события. При повторной отправке используйте прежний ID.

```python
await send_event(crm_url, 'food_porn', secret, 'customer.upsert', {
    'external_user_id': str(telegram_user_id), 'chat_id': str(telegram_user_id),
    'name': name, 'phone': phone, 'language': 'uk',
}, event_id=f'customer:{telegram_user_id}:updated:{change_id}')

await send_event(crm_url, 'food_porn', secret, 'product.upsert', {
    'sku': 'menu-3-days', 'title': 'Меню на 3 дня', 'price': '750.00', 'currency': 'UAH',
}, event_id='product:menu-3-days:version-1')

await send_event(crm_url, 'food_porn', secret, 'order.upsert', {
    'external_user_id': str(telegram_user_id), 'external_id': str(menu_id),
    'title': 'Меню на 3 дня', 'status': 'pending', 'amount': '750.00', 'currency': 'UAH',
    'items': [{'sku': 'menu-3-days', 'quantity': 1, 'unit_price': '750.00'}],
}, event_id=f'menu:{menu_id}:paid')

await send_event(crm_url, 'food_porn', secret, 'payment.upsert', {
    'external_user_id': str(telegram_user_id), 'external_id': transaction_id,
    'order_external_id': str(menu_id), 'provider': 'portmone',
    'status': 'pending', 'amount': '750.00', 'currency': 'UAH',
}, event_id=f'payment:{transaction_id}:paid')

# Для второго бота с зарегистрированным в CRM ключом:
await send_event(crm_url, bot_key, secret, 'lead.upsert', {
    'external_user_id': str(telegram_user_id), 'external_id': str(request_id),
    'title': 'Разработка корпоративного портала', 'service': 'portal',
    'budget': '40000.00', 'currency': 'UAH',
}, event_id=f'lead:{request_id}:created')

await send_event(crm_url, bot_key, secret, 'ticket.upsert', {
    'external_user_id': str(telegram_user_id), 'external_id': str(ticket_id),
    'title': 'Нужна правка формы', 'description': 'Описание запроса',
}, event_id=f'ticket:{ticket_id}:created')

await send_event(crm_url, bot_key, secret, 'bot.heartbeat', {}, event_id=f'heartbeat:{minute_utc}')
await send_event(crm_url, bot_key, secret, 'bot.error', {
    'severity': 'error', 'component': 'checkout', 'message': 'Payment gateway timeout',
}, event_id=f'error:{error_uuid}')
```

Подписка на маркетинговые сообщения передается отдельным событием `customer.consent` с `consent: true`, **только после реального согласия пользователя**, и `consent: false` при отзыве. Другие типы: `customer.activity` с `kind` и `summary`, `customer.blocked` с `blocked`. Если один и тот же человек есть в разных ботах, автоматического слияния по телефону нет; это исключает случайное смешение данных. Передавайте `product.upsert` до `order.upsert` с позициями; сумма позиций должна совпасть с суммой заказа.

Импорт Food_Porn (разовый или повторный, идемпотентный по связке бот/ID; исходный `postgresql+asyncpg://` URL приводится к драйверу `psycopg`):

```bash
python -m integrations.food_porn_import --source-url "$FOOD_PORN_DATABASE_URL" --dry-run
python -m integrations.food_porn_import --source-url "$FOOD_PORN_DATABASE_URL"
```

Импортирует клиентов и меню, без генерации платежей: в исходных моделях нет суммы транзакции. Исходный флаг `is_paid` отображается как `reported_paid` и не становится выручкой. Укажите URL исходной базы в зашифрованном поле `source_database_url` карточки `food_porn` либо в `FOOD_PORN_SOURCE_DATABASE_URL` в `.env`, затем откройте `/integrations` или запустите worker: первая загрузка произойдет сразу, далее раз в 15 минут. Консольная команда импорта пока читает только `.env`. Если исходная и CRM базы Neon совпадают, URL могут быть одинаковыми; CRM использует префикс `crm_` для своих таблиц. **Перед миграциями общей базы проверьте отдельную Neon branch или резервную копию.**

Платежные ключи каждого бота вводятся в `/bots/{id}/configure`. Старые общие значения `PORTMONE_LOGIN`, `PORTMONE_PASSWORD`, `PORTMONE_PAYEE_ID` либо `WAYFORPAY_MERCHANT_ACCOUNT`, `WAYFORPAY_SECRET_KEY` из `.env` применяются только к Food Porn до переноса настроек в его карточку. Для сверки бот должен отправить подписанные `order.upsert` и `payment.upsert` с **одинаковой ожидаемой суммой, валютой и точным номером заказа, переданным провайдеру**. Подключение только базы Food_Porn не создаст выручку: его `menus` не содержат сумму. LiqPay и PayPal Orders v2 также сверяются непосредственно у провайдера; Stripe остаётся записью без сверки.

**Важно для Food_Porn:** в изученном снимке бота `app/bot/handlers/payment.py` задает `is_paid = True` и выдает материалы по нажатию кнопки без платежа; `app/api/portmone_webhook.py` доверяет входящему `STATUS/RESULT`. Перед публикацией оплаты удалите демонстрационную ветку и проверяйте статус через Portmone с номером заказа, суммой и магазином. Это изменение нужно внести в исходный проект бота отдельно; CRM не меняет поведение внешнего процесса. Старую `app/admin_app.py` также не выставляйте наружу без замены ее фиксированного пароля и секрета сессии.

## Google Cloud Run

Создайте отдельный контейнер для веб-сервиса (`Dockerfile`, команда по умолчанию) и Cloud Run worker pool для `python -m crm.worker`. Используйте Neon URL с `postgresql+psycopg://` и TLS (`sslmode=require`), Secret Manager для `SESSION_SECRET`, `BOT_INGEST_SECRETS`, `BOT_TOKENS`, `DATABASE_URL`. Перед запуском веб-сервиса **отдельно** исполните `alembic upgrade head` и `python -m crm.cli create-admin` с доступом к базе. Веб-процессу не нужны исходные токены ботов; worker-процессу нужны `BOT_TOKENS`. Установите `COOKIE_SECURE=true`, HTTPS, не размещайте административный интерфейс без ограничения доступа в публичном интернете. Для рассылок предусмотрена одна реплика worker: это гарантирует задержку между отправками. Несколько worker-процессов потребуют общего ограничения частоты сообщений.

Сервис можно запустить с любой другой платформы, где есть Python и PostgreSQL. Если worker упадет после запроса в Telegram, неопределенные доставки получают `unknown` и не пересылаются автоматически, чтобы не создать дубли. Сопоставьте такой статус с логами Telegram вручную.

## Границы готовности

CRM исполняется автономно с собственными таблицами, но интеграция второго бота и точное соответствие существующей Neon схеме потребуют его исходники и структуру таблиц. Мобильный режим показывает **таблицы этой CRM**, а не произвольные чужие таблицы Neon. Полные рабочие формы доступны в адаптивном интерфейсе по тем же адресам, системный просмотр таблиц остаётся read-only. Реальные токены, учетные данные Neon/платежных систем и Google Cloud в архив не включены; без них сведения от внешних систем не появятся. Нет подключенного магазина с оформлением заказа, расчетов доставки, возвратов и автоматического исполнения заказов: текущая коммерция охватывает каталог, учет заказов и проверку оплаты.
