# OmniFactory CRM 1.14 — Neon и базы проектов

## Возможности

| Действие | Реализация |
|---|---|
| Каталог проектов, веток и баз Neon | Только чтение через Neon API, меню «Neon · базы» |
| Источник данных | SQL URL для отдельного бота, с необязательной привязкой к CRM проекту; реквизиты Fernet |
| Локальная СУБД | PostgreSQL, MySQL/MariaDB и SQLite на сервере CRM |
| Структура | Проверка доступности, снимки таблиц, полей, PK/FK и индексов |
| Данные | Просмотр 25 строк за раз; секретные поля скрываются по имени |
| Импорт | Ручные пакеты по 200 клиентов, услуг, заказов и неподтверждённых платежей; повторное выполнение без дублей по ID |

Neon API не отдаёт строки таблиц. SQL подключение с правами SELECT требуется для каждого источника. В CRM не загружаются все таблицы автоматически; схему и карты полей выбирает администратор. Статус «paid» из произвольной базы не подтверждает банковский платёж. События и воронки пока доступны в просмотре таблиц, автоматическая бизнес-интерпретация зависит от схемы конкретного проекта. Продолжает работать отдельный адаптер Food Porn.

## Установка в Windows PowerShell

Остановите CRM через Ctrl+C. В PyCharm откройте терминал **в корне проекта** `omnibot_crm`. Убедитесь, что установлен предыдущий архив 1.13.2. Скачайте ZIP этого обновления в Downloads.

```powershell
$ErrorActionPreference = 'Stop'
$archive = Get-ChildItem "$env:USERPROFILE\Downloads" -Filter '*1_14*Neon*Source*.zip' -File | Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $archive) { throw 'Архив 1.14 не найден в Downloads' }
Expand-Archive -LiteralPath $archive.FullName -DestinationPath '.\_crm_update_1_14' -Force
.\.venv312\Scripts\python.exe .\_crm_update_1_14\apply_update.py --check
```

До миграции сохраните резервную копию **вашей фактической базы CRM**. При стандартном `DATABASE_URL=sqlite:///./crm_local.db`:

```powershell
Copy-Item '.\crm_local.db' ".\crm_local_before_1_14_$(Get-Date -Format 'yyyyMMdd_HHmmss').db"
.\.venv312\Scripts\python.exe .\_crm_update_1_14\apply_update.py --apply
.\.venv312\Scripts\python.exe -m alembic upgrade head
.\.venv312\Scripts\python.exe -m alembic current
.\.venv312\Scripts\python.exe .\launcher.py start
```

Ожидаемая ревизия — `0015_neon_source_workspace`. Если CRM уже использует Neon как **свою** БД, создайте снимок/резервную копию этой базы до миграции средствами Neon. Установщик не меняет существующий `.env` и не копирует саму БД.

### Подключение каталога Neon

Добавьте в `.env` CRM и перезапустите:

```dotenv
NEON_API_KEY=ваш_ключ_api_neon
NEON_ORG_ID=
```

Для персонального ключа организации задайте `NEON_ORG_ID=org-...`; для ключа самой организации оставьте пустым. Ключ не показывается на страницах и не подставляется в настройки ботов. Войдите как владелец, откройте «Neon · базы» и найдите Project ID, Branch ID и имя базы. API каталог необязателен, если у вас уже есть SQL URL.

### Подключение данных проекта

1. Создайте в Neon PostgreSQL роль только с `SELECT` к нужной базе и схеме. Скопируйте её connection string. `DATABASE_URL` в `.env` CRM не меняйте: это адрес внутренней БД CRM.
2. В CRM откройте «Боты → ваш бот → База данных», задайте имя источника, тип Neon, необязательный CRM проект, Neon Project ID / Branch ID / database и SQL URL. Для MySQL потребуется доверенный `ssl_ca` в URL; для локального SQLite укажите существующий файл `.db`, `.sqlite` или `.sqlite3` **на компьютере/сервере, где работает CRM**.
3. Нажмите «Проверить схему», затем «Просмотр строк» для нужной таблицы.
4. В таблице сохраните карту `customer` и колонку `source_id` — одиночный PK либо одиночный уникальный индекс. Сопоставьте `name`, `email`, `phone`, `telegram_user_id` по наличию.
5. Выполните «Импорт 200». Для `order` и `payment` привяжите `customer_id` к **исходному ID клиента**, `amount` к сумме, `currency` к ISO-коду. Сначала импортируйте клиентов, затем заказы и оплаты. Укажите смещение 200, 400 и так далее для следующих пакетов. Для `product` укажите `amount` и при наличии `title`.
6. Проверьте соответствующие вкладки бота. Импортированные оплаты сохраняются со статусом `pending` и не должны учитываться как подтверждённая выручка до сверки.

## Откат кода

Установщик печатает путь `.crm_update_backups\neon_1_14_...`. Остановите CRM, восстановите код:

```powershell
.\.venv312\Scripts\python.exe .\_crm_update_1_14\apply_update.py --rollback '.\.crm_update_backups\neon_1_14_YYYYMMDD_HHMMSS_XXXXXX'
```

Подставьте напечатанный каталог. Миграция `0015` намеренно остаётся: удаление её файла порвёт цепочку Alembic. Чтобы полностью вернуть прежнюю схему и содержимое, восстановите сохранённую перед установкой базу CRM и код из резервной копии, предварительно остановив CRM.
